# Patina Linux v1.9.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Validate upgrade continuity through a signed release candidate, then publish v1.9.0 as the first stable standalone Patina Linux release.

**Architecture:** Freeze feature work after identity, detachment, Windows removal, and size optimization. Publish a signed prerelease candidate, test both installer-specific updater paths with an isolated 1.8.3 test client, then change only version/changelog metadata for the final release.

**Tech Stack:** Tauri updater, GitHub Actions/Releases, signed AppImage and DEB, release policy scripts, GNOME/Firefox/Chromium extensions.

**Reference:** `docs/superpowers/specs/2026-07-04-patina-linux-independent-project-transition-design.md`

---

### Task 1: Freeze and Audit the v1.9.0 Scope

- [ ] **Step 1: Require clean standalone `main`**

Verify `fork=false`, clean worktree, `main == origin/main`, successful Verify, restored Secrets, and no pending feature work.

- [ ] **Step 2: Audit specification acceptance criteria**

Check identity/path compatibility, Windows boundary, size report, updater manifest tests, documentation, and extension signatures.

- [ ] **Step 3: Confirm release assets and signing key**

Verify the local public key and GitHub Secret names without printing values.

### Task 2: Prepare and Publish v1.9.0-rc.1

**Files:**
- Modify through script: `package.json`, `package-lock.json`, `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock`, three Tauri configs
- Modify: `CHANGELOG.md`

- [ ] **Step 1: Add the `1.9.0-rc.1` changelog section and App note**

- [ ] **Step 2: Run version sync and verify all files**

Run `npm run release:sync-version -- 1.9.0-rc.1`, then version/changelog validation.

- [ ] **Step 3: Run full release validation**

Run `npm run release:check` and `git diff --check`.

- [ ] **Step 4: Commit and request explicit tag/push confirmation**

Do not create or push `v1.9.0-rc.1` without user confirmation.

- [ ] **Step 5: Push tag and monitor Publish Linux Release**

Require all six assets and a three-target `latest.json`. Confirm the release is marked prerelease.

### Task 3: Test Signed DEB and AppImage Upgrades

**Files:**
- Temporary clone outside the main worktree, based on tag `v1.8.3`
- Temporary Tauri config override pointing to the explicit RC release `latest.json`

- [ ] **Step 1: Back up current user data and autostart files**

Do not run upgrade smoke without a verified backup of `~/.config/Patina`, `~/.local/share/Patina`, and `~/.config/autostart/Patina.desktop`.

- [ ] **Step 2: Build an isolated 1.8.3 DEB test client with only the updater endpoint overridden**

Install it in the test environment, trigger update, accept system authorization, and verify it installs the RC DEB rather than AppImage bytes.

- [ ] **Step 3: Repeat with an isolated 1.8.3 AppImage test client**

Verify the updater selects the RC AppImage and relaunches successfully.

- [ ] **Step 4: Verify post-update continuity**

Check database/settings, storage anchors, GNOME D-Bus, browser extensions, API token, autostart, tray, and Patina Linux display surfaces.

- [ ] **Step 5: Record results in the v1.9.0 package report**

If either updater path fails, stop. Do not prepare the stable tag.

### Task 4: Prepare the Stable v1.9.0 Metadata

- [ ] **Step 1: Change version from RC to `1.9.0` only after RC smoke passes**

- [ ] **Step 2: Finalize CHANGELOG and release notes**

Cover independent project identity, Linux-only boundary, package-aware updater, preserved data/protocol identities, and measured size reduction.

- [ ] **Step 3: Run minimum and release validation**

Run:

```bash
npm test
npm run test:replay
npm run build
npm run release:check
npm run release:validate-version-files -- 1.9.0
npm run release:validate-changelog -- 1.9.0
git diff --check
```

- [ ] **Step 4: Commit and push `main`**

Do not tag yet. Confirm Verify succeeds on the exact commit.

### Task 5: Publish and Verify v1.9.0

- [ ] **Step 1: Request explicit user confirmation for tag and release**

- [ ] **Step 2: Create and push annotated `v1.9.0` tag**

- [ ] **Step 3: Monitor Publish Linux Release to success**

- [ ] **Step 4: Verify release title and all assets**

Require `Patina Linux v1.9.0`, AppImage, DEB, GNOME zip, Chromium zip, signed Firefox XPI, and `latest.json`.

- [ ] **Step 5: Verify updater manifest routing and signatures**

Require `linux-x86_64`, `linux-x86_64-appimage`, and `linux-x86_64-deb`, with generic fallback still pointing to AppImage.

- [ ] **Step 6: Run immediate production endpoint smoke**

Check update discovery from a clean 1.8.3 client and launch both final packages. If a release-blocking fault appears, stop automatic distribution and follow the documented rollback/yank procedure.

- [ ] **Step 7: Archive completed working specs/plans**

Move inactive one-off documents to `docs/archive` and keep long-lived truths in top-level docs.
