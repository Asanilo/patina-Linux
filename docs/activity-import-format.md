# 活动导入格式

## 1. 文档定位

本文定义 Patina 平台中立活动 CSV 的稳定输入契约。它用于从其他工具或脚本迁移历史活动，不替代 Patina 的自动追踪主路径。

当前只承诺本文格式。Tai、Taix、ActivityWatch 或其他产品的原生导出需要先在外部转换；Patina 暂不内置这些来源适配器。

## 2. 文件要求

- 文件扩展名为 `.csv`，内容使用 UTF-8，可带 UTF-8 BOM。
- 文件上限为 128 MiB，记录上限为 250,000 条。
- 第一行必须严格按以下顺序包含 8 列：

```csv
record_type,start_time,end_time,duration_ms,exe_name,app_name,title,category
```

- 时间使用带 UTC 偏移的 RFC 3339，例如 `2026-08-31T09:30:00+08:00` 或 `2026-08-31T01:30:00Z`。
- `exe_name` 是非空的应用标识，可使用 Linux desktop ID、进程名或 Windows 可执行文件名，不要求 `.exe` 后缀。
- `app_name`、`title` 和 `category` 可为空。

## 3. 记录类型

### 3.1 `exact_session`

精确会话必须提供 `start_time`、`end_time` 和正数 `duration_ms`。结束时间必须晚于开始时间，时间差与 `duration_ms` 的误差不能超过 1 秒。

精确会话可以带标题，并可进入 History 时间线。与本机会话重叠的部分由本机会话覆盖；多个外部精确会话重叠时按稳定输入顺序保留一条。

```csv
exact_session,2026-08-31T09:00:00+08:00,2026-08-31T09:30:00+08:00,1800000,org.gnome.Terminal,Terminal,Shell,Development
```

### 3.2 `hour_bucket`

小时汇总必须留空 `end_time` 和 `title`，`duration_ms` 必须大于 0 且不超过 3,600,000。

小时汇总只表达该小时内的总量，不表达精确发生位置，因此只参与 Dashboard、Data 等聚合统计，不进入 History 或活动详情时间线。同一小时存在本机或外部精确事实时，小时汇总只使用剩余容量；多个小时汇总竞争剩余容量时按请求时长成比例分配。

```csv
hour_bucket,2026-08-31T10:00:00+08:00,,600000,org.gnome.Terminal,Terminal,,Development
```

## 4. 预览、提交与去重

导入分为预览和提交两步：

1. 预览解析有效记录、重复记录和错误行，并计算整个文件的 SHA-256 指纹。
2. 提交时重新读取文件；如果指纹与预览不一致，拒绝提交并要求重新预览。
3. 有效行可以在存在无效行时单独提交；设置页会展示错误数量和前 12 条错误。
4. 记录按类型、时间、时长、应用标识和标题生成稳定指纹。文件内重复和已有导入记录都会跳过。

为兼容电子表格防公式注入写法，文本值以单引号保护且后续内容以 `= + - @` 开头时，Patina 会移除这一层保护单引号。

## 5. 所有权与数据安全

- 每次实际写入都会创建一个独立导入批次；没有新记录时不创建空批次。
- 删除批次只级联删除该批次拥有的外部记录，不修改本机追踪会话。
- 外部记录保存在 `import_*` 事实表，不写入原生 `sessions` 表。
- 手动备份和定时备份都包含导入批次、精确会话和小时汇总；恢复后会重新核对批次数量。
- 历史清理、标题清理和按应用删除会同时处理对应的外部记录，并清理空批次。

当前桌面 SQLite 读模型已组合这些事实。HTTP / MCP 统计尚未承诺包含外部导入记录；在 Rust 共享读模型完成前，外接分析应把该限制视为明确边界。
